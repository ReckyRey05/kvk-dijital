# FAZ 11.9 — RESTAURANT SESSION / ORDER / INVENTORY REALTIME CONSISTENCY REPAIR

## 1. SESSION ARCHITECTURE (TABLE ID ≠ SESSION ID ≠ ORDER ID ≠ PAYMENT ID)
- **Table ID (`m-1`, `m-4`):** Restorandaki fiziksel masayı temsil eder. Gün boyunca birden fazla oturum açabilir.
- **Session ID (`sess_...`):** Belirli bir müşteri grubunun o masadaki aktif oturumudur.
- **Order ID (`ord_...`):** Belirli bir session'a bağlı sipariş adisyon kaydıdır.
- **Payment ID (`pay_...`):** Belirli bir session ve siparişlere ait finansal ödeme işlemidir.

Her yeni oturum açıldığında bağımsız bir `sessionId` atanır. Önceki oturumun `CLOSED`, `PAID` veya `COMPLETED` durumu yeni açılan oturuma kesinlikle sızamaz.

---

## 2. TABLE, ORDER & PAYMENT LIFECYCLES

```
[QR SCAN / BOŞ MASA] ──> Yeni Session Başlat (activeBillTotal = 0)
                               │
[MÜŞTERİLER KATILIR] ───> Host / Misafir Rolleri (Realtime Presence)
                               │
[SİPARİŞ VERİLİR] ─────> Order A (PREPARING -> READY -> SERVED) [UNPAID]
                               │
[İLAVE SİPARİŞ] ────────> Order B (PREPARING) [UNPAID]
                               │
[KASA ADİSYON TOPLAMI] ─> SUM(Session Unpaid Orders) = Order A + Order B
                               │
[KASA NAKİT KAPAT] ─────> 1. Orders -> COMPLETED & PAID_CASHIER
                         2. Table -> EMPTY & activeBillTotal = 0
                         3. Connected Clients -> "Afiyet Olsun!" (FINISHED Screen)
                         4. Participants & Shared Cart -> Purged
```

---

## 3. SHARED CART CONCURRENCY & ATOMIC MERGE
- iPhone ve Android aynı milisaniyede ürün eklediğinde (örn: iPhone Burger, Android Pizza) Firestore transaction ve sunucu seviyesinde atomik append/merge yapılarak **0 Lost Update** sağlanır (`[Burger, Pizza]`).
- Aynı ürün eklendiğinde (`Burger + 1`, `Burger + 1`) miktar atomik olarak toplanır (`quantity = 2`).

---

## 4. INVENTORY & MENU REALTIME BROADCAST
- Yönetici veya mutfak tarafından stok tükendiğinde veya `toggleItemAvailability(itemId)` yapıldığında sunucuya `UPDATE_MENU_ITEM` aksiyonu iletilir.
- `onSnapshot` / `pollServer` aracılığıyla PC Kasa, iPhone Müşteri, Android Müşteri, KDS ve Garson ekranlarında ürün anında "Tükendi" rozetine geçer ve sepete ekleme butonu devre dışı kalır. Sayfa yenileme gerekmez.

---

## 5. SEÇİLİ MASAYI SIFIRLA (`RESET_SINGLE_TABLE`)
- Kasa veya Yönetim ekranından tek bir masa seçilerek sıfırlanabilir.
- O masanın aktif oturumu, sepeti, katılımcıları ve çağrıları temizlenir, masa `EMPTY` ve `0 TL` durumuna gelir.
- Diğer masalar ve geçmiş finansal sipariş geçmişi etkilenmez.

---

## 6. SİPARİŞSİZ MASA TAŞIMA (EMPTY SESSION TRANSFER)
- Henüz sipariş verilmemiş ancak masada oturan müşterilerin (katılımcılar ve paylaşımlı sepet) bulunduğu masalar hedef masaya taşınabilir.
- Taşınan müşteriler yeni masanın QR URL'sine yönlendirilir ve oturumları korunur.
